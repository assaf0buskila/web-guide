## BUILD STRATEGY - WORK IN PHASES (do not try to one-shot everything)
This is a large build. Work in ordered phases and confirm `npm run build` passes between
each one before moving on. This keeps quality high and avoids a half-broken mega-output.
- Phase 1 - Foundation: scaffold Vite + React + TS + Tailwind, wire the palette tokens,
  set up Hebrew RTL, fonts, Lenis smooth scroll, scroll-progress, and the section shells
  with real Hebrew copy. Ship a clean, readable page first.
- Phase 2 - 3D bubble cluster: build the lazy-loaded R3F/Rapier section + static fallback.
- Phase 3 - Ping-pong chat thread + the pinned Build Path scrollytelling.
- Phase 4 - SEO/LLMO files, GA4 wiring, accessibility pass (run ux-critique), performance
  pass, responsive pass, README.
Verify the build after each phase. A polished page that nails phases 1-2 beats a sprawling
one where everything is 70% done.

## RTL & HEBREW CORRECTNESS (do it properly, not as an afterthought)
Hebrew must be a first-class layout, not LTR-with-a-dir-flag. Enforce all of this:
- `<html lang="he" dir="rtl">`. The whole layout mirrors; reading flows right-to-left.
- Use CSS LOGICAL PROPERTIES everywhere (margin-inline / padding-inline / inset-inline /
  start/end), never hardcoded left/right. In Tailwind use logical/`rtl:` utilities so spacing,
  alignment, and order mirror automatically. No physical `ml-`/`mr-`/`left-`/`right-` for layout.
- Bidi isolation for every embedded LTR run (English names, URLs, file paths, numbers, code,
  ratios like 9:16): wrap in `<bdi>` or `unicode-bidi: isolate` so neighboring Hebrew and
  punctuation don't flip. "AI" must never render as "IA"; commas/periods stay on the correct side.
- Mirror DIRECTIONAL UI for RTL: scroll cues, "next/prev" arrows, the progress rail and the
  Plan -> ... -> Ship map flow right-to-left; slide-in animations enter from the correct (right) side;
  any chevrons/arrows are flipped. Logos and the 3D canvas are direction-neutral - leave them.
- Fonts: the Hebrew display/body fonts (Frank Ruhl Libre / Heebo / Assistant) must carry the
  Hebrew subset; the Latin grotesk (Space Grotesk) is for English tech terms ONLY and must
  never be the fallback for Hebrew text (that causes tofu/□). Set a Hebrew-capable fallback
  in the font stack. Verify no missing-glyph boxes anywhere.
- Hebrew line-height ~1.6, comfortable letter spacing (Hebrew has no caps - don't fake it).
- Test RTL at every breakpoint: no clipped text, no horizontal scroll, no element that
  silently assumed LTR (especially the chat thread, the Build Path rail, and the deploy steps).

## DESIGN QUALITY BAR (HIGH-PROFESSIONAL) - MAKE IT LOOK DESIGNED, NOT GENERATED
The page must read like a designer-crafted editorial product page, not a generic AI/SaaS
template. Hold this bar throughout:

Typography (Hebrew-first, premium):
- Use real Hebrew webfonts, not system defaults. Recommended pairing:
  - Display/headings (Hebrew): "Frank Ruhl Libre" (editorial serif) OR "Heebo"/"Ploni" bold.
  - Body/UI (Hebrew): "Heebo" or "Assistant".
  - Latin tech terms: a grotesk like "Space Grotesk" (NOT Inter/Arial). Harmonize sizes so
    Hebrew and Latin sit on the same baseline.
- Load via preconnect + `display=swap`, subset Hebrew, and avoid layout shift.
- Strong type scale (e.g. 1.25 ratio): oversized display headings, clear H2/H3, comfortable
  16-18px body, generous line-height (~1.6 for Hebrew). One H1 only.

Layout & rhythm:
- 4px spacing base; generous section padding (96-160px desktop, 56-72px mobile).
- Reading column max ~680px; full layout max ~1200px. Use real whitespace.
- Editorial, slightly off-axis compositions and asymmetric splits - avoid the centered
  card-stack SaaS look. Strong grid, intentional alignment, no crowding.

Motion (restrained and consistent - tokenize it):
- Reveal: fade + 16-24px rise, duration ~0.6s, ease `cubic-bezier(0.22, 1, 0.36, 1)`.
- Stagger children ~0.06-0.08s. Parallax max ~40px. No bounce, no random timings.
- Everything respects `prefers-reduced-motion` (content stays, motion stops).

Finish & restraint:
- Subtle film grain / paper texture on light sections; soft, realistic shadows; thin
  hairline borders in Cloud Light. NO heavy glows, NO neon, NO purple/cyan AI gradients.
- Consistent corner radius, consistent icon weight, consistent button styles.
- Anti-slop gate before "done": if a section looks like a default template, redesign it.

## SIGNATURE SECTION 2 - 3D AI STACK BUBBLE CLUSTER
Recreate the glossy floating-bubble cluster from this reference implementation:
`https://github.com/kevingoyal2006/Portfolio-Website/blob/main/src/components/TechStack.tsx`

Also study the live reference for spacing, motion feel, and the way the bubble moment sits
inside a portfolio page:
`https://kevingoyal.vercel.app/`

Build it as its own lazy-loaded React component so 3D code never blocks the rest of the page.

Core technique:
- `<Canvas>` transparent background:
  `gl={{ alpha: true, stencil: false, depth: false, antialias: false }}`
- Camera:
  `position={[0, 0, 20]}`, `fov={32.5}`, `near={1}`, `far={100}`
- `onCreated` sets `toneMappingExposure = 1.5`.
- Use about 28-32 balls.
- Use `SphereGeometry(1, 28, 28)`.
- Random scale from `[0.7, 1, 0.8, 1, 1]`.
- Use `@react-three/rapier` physics with no gravity.
- Each ball:
  - `RigidBody`
  - `linearDamping={0.75}`
  - `angularDamping={0.15}`
  - `friction={0.2}`
  - `BallCollider`
  - every frame applies an impulse toward the center so the balls gather into a tight cluster.
- Cursor interaction:
  - A kinematic pointer body follows the mouse.
  - The pointer has a `BallCollider`.
  - Hovering shoves the balls gently.
- Section background: this is one of the intentional immersive DARK sections. Use a Slate
  Dark `#191919` (to `#262625`) background so the glossy balls and the Book Cloth Claude
  ball pop against the otherwise ivory page.
- Lighting:
  - `ambientLight`
  - `spotLight` (castShadow)
  - `directionalLight`
  - `Environment` - a neutral drei preset like `"studio"` or `"city"`, or a small custom
    `.hdr` in `/public/models/`. Keep reflections clean and neutral, not colored.
- Post-processing:
  - `EffectComposer`
  - `N8AO` for soft contact shadows between balls. AO color = Slate Dark `#191919`
    (NOT purple - stay inside the palette), aoRadius ~2, intensity ~1.15.
- Activate physics only when the section is visible.
- Pause render loop when offscreen.
- Cap DPR: `dpr={[1, 1.5]}`.

Material baseline for ALL balls (glossy, premium, on-brand): `MeshPhysicalMaterial`
with metalness ~0.5, roughness ~0.9-1.0, clearcoat ~0.1, emissive white at
emissiveIntensity ~0.3 (and emissiveMap = the logo texture for logo balls so the marks
stay legible under the AO). Logo balls keep a clean white/ivory ground so the mark reads.

The five ball styles (assign across the ~28-32 balls; logo balls are the visual focus):
- GPT ball:    glossy ball, white/ivory ground, the OpenAI "knot" mark centered in Slate
               Dark `#191919`. Reference: `ref/Ball affect/1.jpg` and `2.jpg`.
- Claude ball: glossy ball in Book Cloth `#CC785C` ground with the white Claude "sunburst"
               mark - the Claude app-icon treatment. Reference: `ref/Ball affect/3.jpg`

- Slate ball:  solid dark glossy ball, no logo, Slate Dark `#191919` / Slate Medium `#262625`.
- Warm ball:   solid Kraft `#D4A27F` or Manilla `#EBDBBC`, no logo.
- Focus spark: ONE or two balls only, Focus blue `#61AAF2`, used as a rare accent.
Rough mix: a few GPT, a few Claude, several Slate, several Warm, 1-2 Focus.

LOGO ASSETS - the marks already exist in `ref/Ball affect/`:
- GPT/OpenAI knot:  `ref/Ball affect/1.jpg` (white on black), `2.jpg` (black on white).
